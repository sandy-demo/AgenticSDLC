15 skenario Agentic SDLC

Pilih level dan persona, atau cari masalah yang ingin kamu coba. S06 dan S14 punya versi lokal/personal serta versi organisasi.

15 skenario tersedia.

S01 · Level 1

Beri agent aturan kerja tim

Dua rencana sudah dibandingkan lewat Copilot di terminal; perbandingan di Chat VS Code belum direkam.

Rani diminta merencanakan fitur riwayat klaim. Kalau klaim tidak ditemukan, apakah API harus mengirim teks biasa atau kode error dan pesan? Bima ingin format { code, message } dengan pesan bahasa Indonesia, tetapi aturan itu belum ada di checkout awal.

Rani, Bima

S02 · Level 1

Ubah fitur di beberapa file

Rencana direkam di VS Code; implementasi kategori dan 25 tes unit diperiksa di draft PR #29.

Di form Klaim baru, karyawan mengisi Taksi bandara, Rp250.000, dan tanggal hari ini. Belum ada pilihan kategori, jadi data yang dikirim ke server tidak membawa kategori dan klaim tersimpan sebagai Lainnya (Other). Bima ingin karyawan bisa memilih Perjalanan dan server menyimpannya sebagai Travel.

Bima

S03 · Level 1

Pakai skill untuk endpoint baru

Endpoint komentar sudah dibuat dan CI lulus pada draft PR #25. Draft belum digabung; foto aktivitas pemuatan skill di VS Code belum disimpan sebagai bukti.

Bayangkan Yoga menerima laporan: komentar untuk klaim #21 belum terlihat. Pembuatan klaim sudah punya log, misalnya { "event": "claim.created", "claimId": 21 }. Route laporan sudah memvalidasi input, tetapi belum punya log sukses seperti itu. Untuk komentar, Yoga ingin { "event": "claim.comment.created", "claimId": 21, "commentId": 1 } tanpa isi komentar. Angka ini hanya contoh.

Rani, Yoga

S04 · Level 2

Delegasikan issue, tinjau draft PR

Percobaan Copilot pertama tidak mengubah file. Percobaan ulang pada draft PR #20 memperbaiki tanggal dan lulus CI.

Karyawan mengisi Taksi bandara Rp250.000, tetapi keliru memilih tanggal besok. Aplikasi latihan masih menyimpan klaim itu. Bima ingin menolak tanggal besok tanpa ikut menolak pengajuan untuk hari ini.

Hendra, Bima

S05 · Level 2

Pulihkan CI merah karena timezone

Draft PR #27 berisi perbaikan tes zona waktu; uji lokal lulus di Jakarta dan Los Angeles.

Rani melihat tes tanggal lulus di Jakarta tapi gagal di Los Angeles. Pada satu momen yang sama, Jakarta sudah 15 Oktober pukul 08.00, sedangkan Los Angeles masih 14 Oktober pukul 18.00. Kalau tes menganggap keduanya sudah tanggal 15, hasilnya tidak konsisten.

Rani, Bima, Yoga

S06 · Level 2 · Opsi organisasi

Delegasikan perubahan dari tiket

Tiket GitHub #19 dan tombol di draft PR #21 sudah diuji. Jalur Jira/Teams belum diuji.

Di form klaim, tombol bertuliskan Submit. Lina ingin pengguna langsung paham bahwa tombol itu mengirim klaim untuk diperiksa Manager. Ia meminta label Ajukan Klaim dan petunjuk yang bisa dibaca saat tombol mendapat fokus keyboard.

Lina, Rani

S07 · Level 2

Modernisasi adapter tanpa big bang

Draft PR #18 menambah tes perilaku lama; draft PR #23 mengganti cara mengambil CSV. Keduanya diuji.

Bima ingin mengganti cara lama modul ekspor meminta file CSV. Sebelum mengganti, ia perlu merekam tiga hasil dari modul lama: respons 200 mengembalikan CSV, koneksi putus dilaporkan sebagai error, dan status selain 200 tidak dianggap sukses.

Hendra, Bima

S08 · Level 3

QA menemukan bug tepat di batas

Draft QA #24 hanya menambah tes. Dua tes membuktikan masalah pada Rp1.000.000; aturan produksi belum diperbaiki.

Sari menguji klaim Rp999.999 dan Rp1.000.000. Yang pertama cukup lewat Manager. Yang kedua harus lanjut ke Finance setelah Manager, tetapi di aplikasi awal keputusan Manager saja sudah cukup.

Sari, Hendra

S09 · Level 3

Tinjau PR dengan tiga spesialis

Tiga profil membaca perubahan di draft PR #20. Ringkasan terbit, tetapi bukan approval manusia.

Sari sudah melihat daftar klaim tampil. Bayangkan ada 10 klaim: aplikasi bisa mengambil daftar sekali, lalu mengambil detail satu per satu sebanyak 10 kali. Reviewer lain perlu mengecek apakah log berisi data pribadi dan apakah perubahan status meninggalkan jejak.

Sari, Dimas, Bima

S10 · Level 3

Latih alur CodeQL Autofix

Satu peringatan tabel pada PR #1 hilang setelah scan ulang. Perbaikannya dibuat biasa, bukan lewat Autofix.

CodeQL, alat pemindai kode, menandai pembuat tabel Markdown di draft workshop. Contohnya, teks CI | e2e yang berisi tanda pemisah harus tetap tampil dalam satu sel, bukan menjadi dua kolom. Dimas ingin melihat hasil tabel setelah patch dan memastikan pemindaian ulang tidak menemukan masalah yang sama.

Dimas, Bima

S11 · Level 3

Setujui desain sebelum implementasi

Usulan desain PR #22 masih menunggu persetujuan. Prototipe di draft PR #37 sudah diuji terpisah.

Manager menekan Setujui untuk klaim Rp1.250.000. Bayangkan server berhasil meneruskannya ke Finance, tetapi koneksi putus sebelum Manager melihat balasannya. Saat permintaan yang sama dikirim ulang, aplikasi awal memberi konflik (409).

Rani, Bima

S12 · Level 4

Sinkronkan API docs lewat draft PR

Koreksi dokumen ada pada draft PR #28. Docs Sync belum menghasilkan draft otomatis.

Tim partner ingin menampilkan daftar klaim. Mereka mengikuti dokumentasi yang menyebut items, padahal GET /claims mengirim daftar dengan nama claims. Respons berhasil, tapi kode partner mencari daftar di tempat yang salah.

Bima, Yoga

S13 · Level 4

Triage issue dan diagnosis CI

Klarifikasi dan diagnosis ditulis fasilitator. Kedua workflow otomatis masih gagal dengan 403.

Yoga menerima tiket yang hanya bilang Aplikasi error, tanpa layar, pesan error, atau langkah mengulang. Di latihan CI, job Los Angeles gagal dengan pesan ECONNRESET (koneksi putus), sementara Jakarta dan tes browser lulus. Kedua kasus butuh informasi yang lebih spesifik.

Yoga, Bima

S14 · Level 5 · Opsi organisasi

Batasi aksi agent dan ukur biaya

Pemeriksaan batas dan audit diuji lokal. Pemakaian AI dicatat dari sesi terpisah, bukan dari dashboard tagihan.

Ibu Maya ingin AI membantu tim, tetapi perlu bukti bahwa tes biasa tetap melewati pemeriksaan normal dan permintaan akses ke lokasi terlindungi ditolak. Hendra juga ingin memisahkan catatan izin tindakan dari catatan pemakaian AI.

Ibu Maya, Hendra, Yoga

S15 · Level 5

Capstone: klaim multi-mata-uang

Tiket induk dan empat pekerjaan sudah ada. Kriteria tes ADR direvisi; fitur multi-mata-uang masih usulan.

Form awal hanya menerima rupiah. Lina ingin karyawan bisa mengajukan biaya perjalanan USD dan SGD. Dengan kurs fiktif Rp15.000 per USD, klaim USD 100 menjadi Rp1.500.000. Karena melewati batas, klaim itu harus lewat Manager lalu Finance.

Lina, Rani, Bima, Sari, Dimas, Yoga, Hendra, Ibu Maya
